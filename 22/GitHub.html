1. Git vs GitHub - Vad är skillnaden?

🔧 Git (lokal versionskontroll)

Git är ett versionskontrollsystem som körs på din dator. Det spårar ändringar i dina filer och låter dig:

  • Spara "snapshots" (commits) av ditt projekt vid olika tidpunkter
  • Gå tillbaka till tidigare versioner
  • Experimentera med nya funktioner i branches
  • Se vem som ändrade vad och när
💡 Viktigt att förstå:

Git är helt lokalt på din dator. Du kan arbeta med Git utan internet och utan GitHub!

☁️ GitHub (fjärr-repository i molnet)

GitHub är en molntjänst där du kan lagra dina Git-repositories online. Det gör det möjligt att:

  • Backup av ditt projekt i molnet
  • Samarbeta med andra utvecklare
  • Dela ditt projekt med världen
  • Ha en professionell portfölj
  • Använda funktioner som Issues, Pull Requests, GitHub Pages

2. Hur Git och GitHub kommunicerar

Git och GitHub "pratar" med varandra genom fyra huvudkommandon:

📤 git push - Skicka ändringar till GitHub

Skickar dina lokala commits till GitHub så andra kan se dem.

git push origin main # Skickar commits från din lokala "main"-branch till GitHub

📥 git pull - Hämta ändringar från GitHub

Hämtar senaste ändringarna från GitHub till din lokala dator.

git pull origin main # Hämtar och integrerar ändringar från GitHub

🔍 git fetch - Kolla vad som finns på GitHub

Kollar vad som finns på GitHub utan att ändra dina lokala filer.

git fetch origin # Laddar ner info om vad som finns på GitHub, men ändrar inget lokalt

📋 git clone - Kopiera ett helt projekt från GitHub

Skapar en lokal kopia av ett GitHub-repository.

git clone https://github.com/kentlundgren/quiz.git # Kopierar hela projektet från GitHub till din dator

3. Vad hände med Quiz 22? (Steg för steg)

Steg 1: Skapade filerna lokalt (Git)

Vi skapade alla filer för Quiz 22 (index.html, script.js, styles.css, bilder, etc.) och la till dem i Git:

git add . git commit -m "initial commit" # Commit-hash: 847568f

Steg 2: Pushade till GitHub

Vi skickade commiten till GitHub:

git push origin main ✓ GitHub fick commit 847568f med meddelandet "initial commit"

Steg 3: Insåg att commit-meddelandet var dåligt

"initial commit" var inte beskrivande nog. Vi ville ändra det till "Add Quiz 22 - initial commit".

Steg 4: Ändrade commit-meddelandet (Git)

Vi använde git commit --amend för att ändra meddelandet:

git commit --amend -m "Add Quiz 22 - initial commit" ✓ Ny commit-hash: 280f3e6 # Git skapade en HELT NY commit (med nytt hash)

Steg 5: Försökte pusha igen (PROBLEM!)

När vi försökte pusha fick vi ett felmeddelande:

git push origin main ❌ ERROR: Can't push refs to remote. Try running "Pull" first to integrate your changes.

4. Varför uppstod problemet?

⚠️ Konflikten:
  • GitHub tror: Den senaste commiten är 847568f ("initial commit")
  • Din lokala Git tror: Den senaste commiten är 280f3e6 ("Add Quiz 22 - initial commit")
  • Problemet: Git och GitHub har olika historik!

🤔 Varför skapas en ny commit-hash?

En commit-hash (som 847568f) beräknas från:

  • Alla filernas innehåll
  • Commit-meddelandet
  • Tidpunkten
  • Författaren
  • Den föregående commitens hash

När du ändrar commit-meddelandet med --amend, ändras dessa data → nytt hash skapas!

💡 Visualisering:

GitHub's vy:

main → 847568f (initial commit)

Din lokala Git's vy:

main → 280f3e6 (Add Quiz 22 - initial commit)

Git ser att dessa är olika commits och vägrar pusha för att inte förstöra GitHubs historik.

5. Lösningen: Force Push

När du är säker på att du vill skriva över GitHubs version med din lokala version, använder du git push --force.

🔒 Två varianter av force push

Alternativ 1: --force (farlig!)

git push --force origin main # Skriver ALLTID över GitHubs version, oavsett vad # ⚠️ Risk: Om någon annan pushat något, förstör du deras arbete!

Alternativ 2: --force-with-lease (säkrare!) ✅

git push --force-with-lease origin main # Skriver bara över om GitHub's version är samma som du tror # ✓ Säkrare: Om någon pushat något, får du ett fel istället

Detta är vad vi använde för Quiz 22!

✅ Resultatet efter force push:

Nu har både Git och GitHub samma commit:

main → 280f3e6 (Add Quiz 22 - initial commit)

Den gamla commiten (847568f) är borta från GitHubs historik.

6. När ska man använda Force Push?

✅ OK att använda force push när:
  • Du arbetar ensam på en branch
  • Du ändrar något i den senaste commiten (t.ex. commit-meddelande)
  • Du fixar ett misstag som du just gjorde
  • Du är säker på att ingen annan har pushat något
❌ Använd ALDRIG force push när:
  • Andra utvecklare arbetar på samma branch
  • Det är en delad branch (som main i ett team-projekt)
  • Du inte är säker på vad som kommer hända
  • Projektet är i produktion och andra använder koden

7. Sammanfattning: Git & GitHub workflow

📋 Typisk workflow:
  1. Lokalt arbete (Git):
    git add . # Förbered ändringar git commit -m "message" # Spara snapshot
  2. Synka med GitHub:
    git pull origin main # Hämta senaste från GitHub först git push origin main # Skicka dina ändringar
  3. Om det blir problem:
    git status # Kolla vad som är fel git log --oneline # Se commit-historik

8. Viktiga kommandon att komma ihåg

# === STATUS OCH INFO === git status # Vad har ändrats? git log --oneline # Se commit-historik git log -1 # Se senaste commit # === LOKALT ARBETE === git add . # Lägg till alla ändringar git commit -m "meddelande" # Spara snapshot git commit --amend -m "nytt meddelande" # Ändra senaste commit # === SYNKA MED GITHUB === git pull origin main # Hämta och integrera ändringar git push origin main # Skicka ändringar till GitHub git push --force-with-lease origin main # Force push (säker variant) # === FEL OCH ÅTERSTÄLLNING === git reset --soft HEAD~1 # Ångra senaste commit (behåll ändringar) git reset --hard HEAD~1 # Ångra senaste commit (ta bort allt)

9. Varför är detta viktigt att förstå?

Genom att förstå skillnaden mellan Git (lokal) och GitHub (molnet) kan du:

  • Förstå varför vissa kommandon funkar eller inte funkar
  • Felsöka problem när de uppstår
  • Arbeta mer effektivt med versionskontroll
  • Samarbeta bättre med andra utvecklare
  • Undvika att förstöra projekt-historiken
🎓 Lärdomen från Quiz 22:

När du ändrar något som redan är pushat till GitHub (som ett commit-meddelande), skapar Git en ny version av historiken. GitHub och din lokala Git har då olika versioner, och du måste explicit säga åt Git att "jag vet vad jag gör, skriv över GitHubs version" med force push.

Använd alltid --force-with-lease istället för --force för säkerhets skull!
